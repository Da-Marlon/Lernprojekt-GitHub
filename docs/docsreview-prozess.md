# Review- und Feedbackprozess

Das Review schützt vor Fehlern und hilft, den Code zu verbessern.

## Ablauf

1. Wenn eine Aufgabe erledigt ist, verschiebt der Assignee das Issue im Project in die Spalte «Review».
2. Eine andere Person als der Assignee prüft die Arbeit. Die eigene Arbeit wird nicht selbst freigegeben.
3. Das Feedback wird als Kommentar im Issue gegeben.
4. Sind Änderungen nötig, gibt der Reviewer dem Assignee Bescheid. Das Issue geht zurück nach «In Progress».
5. Ist alles in Ordnung, wird das Issue mit einem Abschlusskommentar geschlossen und nach «Done» verschoben.

Eine Aufgabe ist fertig, sobald das Issue geschlossen ist und im Project in «Done» liegt.

## Regeln für Feedback

- Konstruktiv und lösungsorientiert
- Sachlich und konkret: Was genau soll geändert werden und warum?
- Wenn möglich mit Verbesserungsvorschlag
